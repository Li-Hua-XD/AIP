# 废墟智援四足机器人比赛系统产品需求文档

文档修订：v0.2　｜　日期：2026-10-31　｜　状态：分阶段实施需求稿

保留原文件名以兼容已有链接；文档修订号与产品阶段 V1/V2 分开。本文为产品范围与验收的主依据，相关技术设计、SDK 缺口报告和实施方案按本稿同步。

## 1 产品目标与比赛依据

项目使用单台 **Unitree Go2 EDU，16 GB / 100 TOPS 拓展坞版本**，在比赛场地完成自主任务。先交付从起点到终点的自主寻路、在线建图和机器人定位，再增加生命目标识别、目标定位、回传与复核。MuJoCo 用于开发、回归和差异测试，真实 Go2 用于分段及全场复现；两端分别验收。

项目范围限定为竞赛场景的移动、建图、定位和后续目标识别。多机协同保留为非必要能力拓展，按比赛大概率仅使用单机安排开发、资源和验收，不纳入 V1/V2 发布门槛。

### 1.1 依据与标注

赛事依据为用户提供的六页[赛题规则](../references/废墟智援_赛题规则文档.pdf)。本文区分“官方要求”“项目决策”“内部建议指标”和“待核验”。产品分期是团队开发顺序，不代表官方免除后续比赛能力要求；V1 通过不能声明已完成整个比赛任务。

| 类别 | 既有赛事依据 | 来源 |
| --- | --- | --- |
| 核心任务 | 运动控制与路径规划；生命目标探测、定位、识别及信息回传 | 第3页 |
| 能力要求 | 地形自适应、弱光识别、动态避障、狭小空间通行、多传感器抗干扰 | 第2页 |
| 场地 | 12×10 m，坡道、S 弯、死胡同分岔、五处乱石、三类隧道 | 第6页 |
| 平台 | 允许商用本体或虚拟机器人；预选存在指定线上平台 | 第3–4页 |
| 评分 | 实操与答辩加权，具体权重与量化阈值待确认 | 第3页 |

### 1.2 硬件基线

| 硬件 | 项目决定 | 使用阶段 |
| --- | --- | --- |
| Go2 EDU 16 GB / 100 TOPS 拓展坞版本 | 已选型，单机；规格按用户提供的配置登记 | V1/V2 共用 |
| 本体自带激光雷达、IMU、本体状态/里程计 | V1 感知输入；到机验证点云、时间戳、外参、可访问接口及质量 | V1 必需能力来源 |
| 本体自带相机 | V1 导航与启动不依赖；有条件可单独用于人工观察 | V2 再评估目标识别用途 |
| RealSense D435i | 可选装，V1 不安装、不模拟为算法必需输入 | V2 按识别与深度定位需求决定 |
| Livox MID360（MID-360）3D 雷达 | 可选装，V1 不使用 | 后续按建图/定位实际缺口决定，不默认与 V2 绑定 |

16 GB / 100 TOPS 是选定硬件配置，不代表已测得持续算法性能。扩展计算单元的系统、架构、SDK/驱动兼容性、散热和可用算力到机冻结。自带雷达具体型号按交付设备确认；官方当前 Go2 页面描述自带 4D 激光雷达，但其版本不应反推用户设备已采用同一批次。[官方 Go2 资料](https://www.unitree.com/go2/)

若自带雷达点云或必要状态不可访问，V1 实机链路记为受阻，先解决官方接口/驱动，不静默把 D435i、MID360 加入 V1，也不以仿真真值替代实机定位。自带雷达的名义视场不等于装机后完整后向或顶部覆盖，须测量机体遮挡和盲区。

## 2 两个导航版本、两个功能阶段

### 2.1 导航版本

| 导航版本 | 任务开始前允许的信息 | 核心行为 | 开发顺序 |
| --- | --- | --- | --- |
| 不背图版 `online_unknown` | 本体与传感器标定、允许运行边界、起点坐标约定；无地图、路线或终点位置 | 每次冷启动建立地图，在线定位、选择可达前沿、规避阻塞并回退，探索过程中抵达终点 | **优先开发、V1 主线** |
| 背图版 `prior_map` | 经允许的先验地图、版本与坐标标定；可选导航路点 | 地图匹配定位，利用先验全局规划，实时更新障碍并重规划 | 在不背图核心闭环稳定后实现 |

“不背图”指不依赖事先记忆的赛道地图，不是运行中不建立地图。它禁止读取 `layout.json` 的内部障碍坐标、`route_waypoints`、`geometry_manifest.json` 的中心线、上次任务地图、场景隐藏标签或固定转向序列；同一任务内的在线地图和返回轨迹可以保留。恢复同一任务须有显式恢复记录；正式冷启动验收必须清空地图和历史分支记忆。

优先不背图的理由是降低对仿真与现场布局一致性的依赖，提高对路线变化的适应能力。这是待验证的工程预期，不承诺任何条件下都更高成功率：在线建图还受传感器覆盖、定位漂移、探索效率和时间预算影响。两版最终使用同组变化场景对比。

**终点位置对不背图算法也未知。** V1 仿真由独立评估器持有终点真值区域，依据机器人真值位置判断是否到达；自主端不接收终点坐标、方向、距离或基于终点距离的奖励。评估器可向任务监督器发送一次终止事件并请求停止，之后核对停稳及位置是否仍在区域内；此事件不作为后续选路提示，也不能用于反复试探区域边界。评估过程和终止事件单独记录。

实机如何验收终点尚未确认，保持 `real_finish_policy=pending`。在确认可执行的验收方式前，可开展实机探索、建图、定位和分段运动验证，但不能宣布实机自动终点判定或完整起终点任务已通过。后续若采用人工/裁判确认，应标注为外部验收；若要求机器人自行发现终点，则必须有其传感器可观察、赛事允许且可验证的判据。未发现新前沿、进入死胡同或探索超时都不等于到达终点。

两版具体规格见[不背图版](./导航方案_不背图版.md)与[背图版](./导航方案_背图版.md)。导航版本与功能阶段独立组合，V2 也可以使用不背图导航。

### 2.2 功能分期与发布门槛

| 阶段 | 必需交付 | 不作为本阶段启动/验收依赖 |
| --- | --- | --- |
| V1 导航建图 | 自带雷达/IMU/状态输入，在线建图定位，起点到终点寻路，障碍处理，停止接管，地图/轨迹/日志导出 | 目标检测、目标坐标、人工目标复核、RGB-D、D435i、MID360 |
| V2 生命目标识别 | 在 V1 上增加目标识别、定位去重、证据、信息回传、人工复核和弱光评测 | 多机协同；D435i/MID360 是否采用由能力验证决定 |
| 可选拓展 | 多机任务分配与地图共享、其他独立评审能力 | 不阻塞单机比赛系统 |

P0 表示**所属阶段**的发布门槛，P1 表示该阶段增强项，P2 表示非必要拓展。V2-P0 不得误读为 V1-P0。在线训练是否为比赛强制要求继续待答疑，不作为 V1 导航的默认技术前提。

### 2.3 用户与任务流程

V1 操作员配置导航版本、探索时间预算及验收模式，检查本体和定位，通过控制台查看正在增长的地图、机器人位置、当前探索子目标、路径和异常，必要时暂停或接管；测试人员比较地图、轨迹、成功率和失败原因。V2 增加目标复核员与目标证据页面。

V1 流程：加载版本及本体配置 → 校验阶段验收模式与传感器 → 空地图初始化定位 → 人工启动 → 观测建图与前沿选择 → 局部规划与安全执行 → 动态重规划或回退 → 独立评估器判定到达并核对停稳 → 导出地图、轨迹和运行记录。

到达终点不要求绘制整场所有区域。地图至少覆盖已行走路径及规划使用的可观测区域，保留未知区域；完整覆盖探索是独立任务目标，不能用无止境探索延迟结束。

## 3 V1 功能需求

### FR01 配置与版本管理｜V1-P0

配置包括 `feature_stage`、`navigation_mode`、本体/传感器版本、终点验收模式、允许边界、限速、停止参数、任务时限及日志目录。仿真世界生成配置与自主输入配置分离；不背图配置拒绝先验地图和固定路线，背图配置校验地图哈希与坐标。

验收：缺项、错误单位、非有限值、模式冲突或非法地图/终点真值输入时阻止启动并指出字段；每次保存配置快照。官方场地细节仍以正式说明为准。

### FR02 自检与启动｜V1-P0

检查雷达、IMU及使用中的本体状态新鲜度、时间/外参、定位初始化、控制通道、停止手段、电量和存储。V1 不检查检测器、RGB-D、D435i 或 MID360 是否在线，也不因为这些未安装阻止启动。

验收：必需输入失败保持待命；首次雷达观测可用于创建起点周围地图，不要求任务开始前已获得全场地图。

### FR03 自主寻路与地形通行｜V1-P0

从起点探索未知环境，依靠在线地图规划可达前沿，逐步建立连通性；终点不作为规划目标输入，由独立评估判定探索过程中是否到达。根据坡度、粗糙度、净空和已验证运控能力限速；只有底层确实支持且通过验证时才请求姿态或步态变化。

验收：通过已定义赛段，记录耗时、路径、碰撞、倾倒和接管；改变障碍布置后重新观测与规划，不依赖固定赛段顺序。超出能力边界停止或寻找合法替代路线。

### FR04 障碍处理与重规划｜V1-P0

持续更新路径占用，障碍进入停止预算时减速或停止，再重规划。静态封路、横穿、突发靠近均需覆盖。地图未知不等于自由空间；只有观测确认的前方自由空间足以停止时才可继续接近未知边界。

### FR05 死胡同与回退｜V1-P0

结合在线分支连通性、近期进展及可用前沿识别死胡同，记录失败原因与地图版本。退出前重新检查后方走廊；后向覆盖不足时暂停接管，不假定自带雷达一定看见后方，也不在窄通道强行转身。失败分支只有在新观测证明条件改变时才解除禁入。

### FR06 通道判定｜V1-P0

使用自带雷达的有效三维观测比较通道截面和实际扫掠包络，输出可通行/阻塞/未知。未知时在入口外补充观测或暂停。圆管按截面检查，不仅比较宽高；隧道1依据实际净空拒绝，不按编号硬编码。无需视觉才能启动此能力；若雷达无法测得关键顶板/侧壁，则不能宣称可通行。

### FR07 运动保护与接管｜V1-P0

安全保护 > 人工 > 自主，控制权变化撤销旧租约。检测命令过期、失联、倾角异常、长时间无进展和控制反馈失效，执行平台支持且验证过的停止。请求发送、接受与实际停稳分别记录，故障解除后人工确认恢复。

### FR11 传感器异常与弱光｜V1-P0 / V2-P1

V1 必须处理雷达/IMU/定位丢帧、延迟、漂移及失效，关键数据不足时停止，不使用过期观测。V2 再加入视觉弱光、遮挡及多传感器退化评测；V1 没有弱光目标识别指标。

### FR12 风险事件｜V1-P1

报告可观测的阻塞、限宽限高与失稳风险，保存触发依据、严重程度及动作。停止联动属于 FR04/FR07 的必需行为，不因风险展示为 P1 而延期。

### FR13 任务、地图与日志导出｜V1-P0，V2 扩展

V1 保存任务状态、轨迹、地图快照、坐标关系、定位质量、导航子目标、分支记忆、事件、控制权、配置和模型版本；完成与异常终止均可导出。记录地图的未知/自由/占据、分辨率、原点、版本和生成来源。V2 再增加目标、证据及复核历史。

### FR14 在线建图与机器人定位｜V1-P0（新增）

利用自带激光雷达、IMU及可用本体状态，输出连续六自由度位姿、定位质量、在线点云/占据地图及供规划使用的地形信息。地图坐标系在起点初始化；全局校正须同步维护路径、前沿及已观测分支的坐标关系；自主地图坐标与仿真评估世界坐标的对应只由评估端维护，不借此向算法注入终点位置。

验收：冷启动不加载旧地图；有独立真值对照的机器人轨迹误差、地图几何误差及定位有效率；无效定位停止。仿真真值定位只算开发调试，不能算 FR14 通过。

### FR15 未知空间探索与终点判定｜V1-P0（新增）

以已知自由空间邻接未知区域的可达前沿为优先子目标，综合可观测增益、路径代价、重访惩罚和风险，不使用隐藏终点的方向或距离。另维护机体实际访问掩码：被雷达看见但机体尚未经过的可达区域仍需生成访问子目标，不能在看完整片区域后直接结束，遗漏只有位置评估器才知道的终点。访问采样间距与最小可验收区域尺度在测试前统一冻结，不依据隐藏终点位置动态调整。保存返回路径、尝试上限和地图版本，避免无限重复探索；不穿越未知或已占据区域。

V1 仿真终点由评估端按位置验收：事先冻结终点区域、机体参考点、位置容差、停稳阈值和保持时长；机器人进入区域后请求停止，保持在区域内且停稳才计成功。擦边后滑出、无效物理状态、碰撞、倾倒、人工导航接管或超时不计自主成功。正常裁判终止信号不计人工导航接管，使用次数和时间仍须记录。

在未知前沿与已知可达未访问区域均无有效候选后输出 `NO_FRONTIER`（兼容错误名，表示无探索/访问候选），探索预算耗尽输出 `EXPLORATION_TIMEOUT`；不能把它们计为到达终点或证明隐藏终点不可达。实机终点验收接口先保留，规则未明确时只允许标为探索试验，结束原因与完整任务验收分开。

### FR16 先验地图导航｜背图版-P0（新增，晚于不背图闭环）

加载带版本和标定的地图，定位对齐后导航；实时观测覆盖过期障碍，发生地图失配时暂停、重定位或经配置进入在线重建模式，并记录模式切换。不能把固定速度时序回放当作背图导航。独立验收，缺少先验地图不影响不背图版启动。

## 4 V2 生命目标识别需求

本章整体不纳入 V1 交付和启动依赖；V2 在冻结目标类别、传感器及算力方案后实现。

### FR08 生命目标识别｜V2-P0

检测官方允许的目标类别，输出类别、置信度、采样时间及证据；使用跨帧确认，覆盖正常光照、弱光、遮挡与相似干扰物。模型、数据来源、预处理及阈值必须可追溯。

### FR09 目标定位与去重｜V2-P0

利用验证过的 RGB-D 或相机与雷达关联方案，将目标转换到地图坐标并保存不确定度、位置有效性及地图版本；无可靠深度或位姿时位置为空。多次观测合并为目标 ID，相邻不同目标不误合并。机器人定位 FR14 与目标定位 FR09 是不同能力。

### FR10 目标回传与人工复核｜V2-P0

显示目标、坐标状态、证据及复核状态，保留操作人和变更历史；断线缓存、按事件编号补传去重。V1 的任务遥测、事件回传和断线处理由 FR07/FR13 承担，不等待本需求实现。

## 5 控制台、状态与接口

V1 三个主要页面：任务配置、运行监控、历史复盘。运行监控显示地图增长、机器人位置、定位质量、当前探索前沿、路径、运动状态及告警。视频和目标列表不是 V1 必需元素；V2 增加目标告警与复核页面。

任务状态：待命 → 自检 → 就绪 → 运行 → 完成，运行可转暂停/故障/终止。探索是运行中的导航子状态，不等于任务失败。完成与终止后新建任务，不直接续跑。停止未确认时持续显示等待或未知，重连不自动恢复运动。

| 对象 | 最小字段 |
| --- | --- |
| 任务 | task_id、feature_stage、navigation_mode、版本、finish_policy、finish_status、时限、状态、结束原因 |
| 位姿 | 采样时间、frame_id、六自由度姿态、速度、状态、协方差/质量 |
| 地图 | map_id、map_revision、source=online/prior、分辨率、原点、观测年龄、未知/自由/占据、文件哈希 |
| 导航 | 子状态、frontier_id、目标/子目标、路径版本、失败分支、剩余预算 |
| 事件/控制 | event_id、task_id、时间、序号、原因；command_id、来源、epoch、有效期、发送/接受/运动状态 |
| 评估端专用 | 终点真值区域、判定参考点、容差、真值轨迹、进入/停稳时刻；不提供给自主端 |
| V2 目标 | target_id、类别、置信度、位置有效性、证据、复核与版本 |

配置与业务操作可重试且幂等，运动命令必须有时效。单调时钟用于本地超时，观测采样时间用于定位与变换，跨设备时延需时间同步依据。仿真、实机、回放模式互斥；回放禁止运动输出。

## 6 指标与统计口径

以下为内部建议，不是官方评分阈值或实测结果。保留已有 Q 编号；阶段适用性是本轮修订重点。仿真/实机、背图/不背图分别统计，不混合样本。

| 编号 | 适用范围 | 指标 |
| --- | --- | --- |
| Q01 | V1 两版 | 每赛段至少10次，成功率≥90%；无碰撞、倾倒与接管 |
| Q02 | V1 两版 | 冻结任务时限后全场10次至少8次成功到终点并导出；不背图每次冷启动 |
| Q03 | V1 两版 | 横穿、封路、突发靠近各10次，零碰撞；停滞不算通行成功 |
| Q04 | V1 两版 | 不可通行条件至少10次全部提前拒绝，另设可通过样本 |
| Q05 | V2 | 正常/弱光目标召回率≥90%/80% |
| Q06 | V2 | 正常/弱光精确率≥90%/85%，重复告警不重复计真阳性 |
| Q07 | V2 | 有效目标位置平面误差中位数≤0.30 m，P95≤0.50 m，同时报告定位有效率 |
| Q08 | V1 事件 / V2 目标 | 正常链路事件生成至显示P95≤1 s，至少100条；V1使用导航/故障事件 |
| Q09 | V1 两版 | 停止请求接受时延P95≤300 ms；另测停稳时间/距离，接受时刻不可观测则明确说明 |
| Q10 | V1 两版 | 10次断线均正确保护，重连不自动运动，缓存事件按ID去重后不丢不重 |
| Q11 | V1 两版 | 受监护连续30分钟运行，无进程崩溃、失控和关键日志缺失 |
| Q12 | V1 / V2扩展 | 完成/异常任务均可导出；V1地图/轨迹/事件、V2再含目标/证据，关联完整率100% |
| Q13 | V1 建图定位，新增 | 报告机器人轨迹ATE/RPE、地图静态表面误差、定位有效率和终点误差；数值阈值见下文冻结流程 |
| Q14 | 不背图优先、两版对比，新增 | 在未参与调参的至少10个变化布局各运行1次，建议≥8次自主到达、全部零碰撞；所有失败保留，两版用相同工况分别报告 |

Q13 必须在到机标定及独立评估条件确定后、正式测试前冻结最大允许定位误差、地图误差、有效率和终点容差，写入 `acceptance_profile`；未冻结或未达到时不得宣布 V1 发布。仿真终点容差按真值区域和参考点定义，不能用算法定位不确定度扩大成功区域。实机终点判据待定，不从仿真容差直接复制。ATE/RPE 记录坐标对齐方法与尺度，不以任意逐段重对齐掩盖漂移；地图只统计有参考真值且被实际观测的静态区域，并报告覆盖范围，不能用全场覆盖率要求替代到终点任务。

Q14 变化包括障碍位置、封闭分支、通道宽度/坡度（保持合法且在能力范围内）、起始偏差与观测噪声。布局/随机种子对自主端隐藏，测试前冻结有效性与可达性；不可达场景单列处置用例，不计入成功率分母凑分。未知终点探索路径长度、耗时、重访次数与接管次数一并报告。

V2 目标测试至少50个独立布置实例、20段无目标负样本，按光照分别统计；训练验证测试按场景或序列拆分。检测和定位指标不能拿来代替 V1 机器人定位误差。
