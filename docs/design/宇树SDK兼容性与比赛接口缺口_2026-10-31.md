# 宇树 SDK 兼容性与比赛接口缺口

核对日期：2026-10-31。依据：本项目 [PRD v0.2](./废墟智援_PRD_v0.1.md)、[技术设计 v0.2](./废墟智援_技术设计文档_v0.1.md)、当前代码和官方 SDK 源码。本报告是现状审计及实施建议，表中的拟建接口尚未实现。

## 0 本轮范围修订

2026-10-31按用户决定调整实施范围；下列固定SDK提交和源码兼容性结论保留，需求优先级以修订PRD为准，不表示已重做实机测试。

- 本体固定为Go2 EDU 16 GB / 100 TOPS拓展坞版本，V1仅使用自带雷达、IMU及本体状态；D435i、MID360为后续选装，V1不使用。
- V1优先不背图，地图与终点位置均未知：在线SLAM、前沿探索、寻路、避障、停止、地图/轨迹导出。仿真终点由独立评估器按真值位置判定，实机终点验收未确认。
- 背图版随后增加先验地图与重定位，版本与V1/V2功能阶段独立。V2再实现生命目标识别、目标定位、证据与复核。
- 多机协同只保留非必要拓展；V1启动不等待图像、深度、检测器或目标链。

方案见[不背图版](./导航方案_不背图版.md)、[背图版](./导航方案_背图版.md)。

## 1 结论与核对范围

目前具备 MuJoCo 中的基础速度行走与简单距离、角度任务，可开始开发上层算法，但还没有完整比赛系统。

- **运动语义可映射**：本地 `move(vx, vy, vyaw)`、`stop()` 可分别适配官方 `SportClient.Move()`、`StopMove()`。
- **官方 SDK 不能直接控制当前仿真**：没有 DDS/RPC 仿真服务，没有官方状态主题；当前虚拟环境也未安装 `unitree_sdk2py`、`cyclonedds`、`rclpy`。这不代表宿主系统中所有环境的安装情况。
- **状态仅部分可转换**：位置、朝向、速度、足端接触来自 MuJoCo 真值；尚无定位有效性、完整传感器契约或实际执行确认。
- **导航、目标探测和业务系统需要实现**：宇树 SDK 可承担实机运动与部分数据获取，不能直接替代本项目的地图、规划、通道判断、目标关联、人工复核及记录系统。
- 当前混合地形模型只有三维速度命令输入；不存在可由上层随意设置的步态编号、机身高度或姿态命令。

官方核对基线固定为：

| 来源 | 固定提交 | 核对内容 |
| --- | --- | --- |
| `unitree_sdk2_python` | `814556d15970dd2ecf1c9984e845ca02ab07e206` | Go2 Sport、RPC、状态 IDL、相机、避障、服务及灯光接口 |
| `unitree_sdk2` | `8e1b927586712edd6a4c29d50dd52dff1e163439` | Go2 C++ Sport 头文件 |
| `unitree_ros2` | `668d1ec5a05d1c38d3306bdca7d59f2ba3581a88` | ROS 接入、状态、激光主题与环境说明 |
| 本地行走模型 | `go2_rl_lab@6c95d9feef4814c25eb6536e61bb38e1d1d718d4` | 当前 `configs/go2_controller.json` 与本地适配器 |

这里的兼容判断基于源码和既有仿真报告；没有进行真实 Go2、DDS 互通或固件能力验收。实体硬件选型已确定；实际固件、服务、自带雷达具体型号、数据接口与拓展坞运行环境仍待到机核验。

## 2 运动接口兼容表

“可适配”表示参数与用途存在对应关系，不表示已经实现官方调用或完全复现实机动作。

| 官方 Go2 接口 | 当前项目状态 | 比赛中的处理建议 |
| --- | --- | --- |
| `Move(vx, vy, vyaw)`，API 1008 | 可适配到 `MujocoGo2.move()`；DDS 未接通 | P0：统一速度入口；前进、转向已测，倒退、侧移需专项验证 |
| `StopMove()`，1003 | 可适配到 `stop()`；仅请求零速度 | P0：增加 `STOPPING/STOPPED/UNKNOWN` 状态及超时 |
| `BalanceStand()`，1002 | 零速度策略可保持站姿，但没有同名服务及独立平衡站立模式 | 仅在定义并验证语义后开放，不能直接宣称等价 |
| `StandUp()` / `StandDown()`，1004/1005 | 未实现起立或趴下过渡 | 实机初始化可能需要；仿真 `reset()` 不能冒充这两个动作 |
| `Damp()`，1001 | 未实现阻尼模式 | 不能简单映射为零速度或切断力矩；停止保护须按本体能力设计 |
| `RecoveryStand()`，1006 | 无翻身恢复策略 | 倾倒后暂停并请求处理，不能用设置位姿伪装恢复 |
| `Euler(roll,pitch,yaw)`，1007 | 当前策略没有姿态命令输入 | 调姿不支持；隧道判断必须使用当前实际包络 |
| `SpeedLevel(level)`，1015 | 有数值速度限值，无官方档位语义 | 项目可定义限速配置，但须区分原厂速度档位 |
| `SwitchJoystick(on)`，1027 | 无官方遥控器切换服务 | 项目仍需自主/人工/保护仲裁；开关不等于控制权租约 |
| `StaticWalk()` / `TrotRun()` / `FreeWalk()` / `ClassicWalk()` 等 | 当前为单一 MoE-CTS 策略，无这些模式选择输入 | 不宣称兼容；由能力配置报告“不支持” |
| `AutoRecoverySet/Get()`，2054/2055 | 未实现 | 不默认启用自动恢复；遵守 PRD 的故障后人工确认恢复 |
| `FreeAvoid()` / `SwitchAvoidMode()` | 无对应仿真服务或避障算法 | 不能仅设置开关就宣称动态避障完成 |
| `Sit/RiseSit`、跳跃、翻滚、倒立、舞蹈等 | 未实现 | 不属于当前 P0；兼容层应明确拒绝，不能返回假成功 |
| `GetServerApiVersion()`，继承自 RPC Client | 无服务端 | 若建设 SDK 桥，必须提供版本探测和明确的支持清单 |

上述方法及 API ID 直接核对 [Go2 Python SportClient](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/go2/sport/sport_client.py)、[Sport API 定义](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/go2/sport/sport_api.py)。本地证据为 [sim_robot.py](../../aip/sim_robot.py) 的 `move/stop/_effective_command`，以及 [控制配置](../../configs/go2_controller.json)。

### 2.1 不能混用的机型与版本接口

本次固定版本的 **Go2 Python SportClient 和 Go2 C++ SportClient 均未公开** `BodyHeight()`、`FootRaiseHeight()`、`SwitchGait()`、`TrajectoryFollow()` 方法。不要把其他机型、旧版本或 README 中的泛化示例当作当前 Go2 的接口承诺。[Go2 C++ 头文件](https://github.com/unitreerobotics/unitree_sdk2/blob/8e1b927586712edd6a4c29d50dd52dff1e163439/include/unitree/robot/go2/sport/sport_client.hpp)

Python 源码虽然定义 `PathPoint`，也不等于实现了路径跟随方法；`EconomicGait` 在该 Python 版本注册了 API 常量，但没有同名公开方法，C++ 头文件则声明了它。选定语言及版本后应逐项检查。

因此前面讨论中的 `SwitchGait()` 只能作为泛指步态切换的例子，不能当作当前 Go2 Python SDK 可直接调用的方法。上下楼和爬坡也不是给当前 SDK 增加一个方法名就能获得的能力。

### 2.2 发送成功、请求接受和运动完成必须分开

官方 `Move()` 使用 `_CallNoReply`，其返回值主要反映发送情况，没有服务端逐条执行应答。`StopMove()` 使用请求应答，但 RPC 返回成功同样不能替代实际停稳判断。[RPC ClientBase 实现](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/rpc/client_base.py)

项目反馈至少区分：`SENT`、`ACCEPTED`、`REJECTED`、`EXPIRED`，以及物理状态 `MOVING/STOPPING/STOPPED/UNKNOWN`。对于实机无应答速度命令，不能伪造 `ACCEPTED` 或声称已精确关联某条实际动作；应保留 `acceptance_known=false`，通过有时间戳的遥测判断后续运动状态。

本地 `move()` 返回 `None`，非法输入抛异常；官方方法返回错误码。统一适配器需转换错误行为，不能让任务算法忽略返回值。

## 3 状态与传感器能复用哪些部分

| 数据/服务 | 官方来源 | 当前仿真 | 按阶段补充 |
| --- | --- | --- | --- |
| 位置、速度、朝向、运动模式 | `SportModeState_`，SDK 常用 `rt/sportmodestate`；具体高/低频流按设备确认 | `RobotState` 仅有位置、yaw、平面速度等；无 DDS | 六自由度位姿、坐标系、采样时间、有效性、定位质量和误差；原厂 position 不默认等于赛场 map 坐标 |
| IMU、关节、电池、本体状态 | `LowState_` / `SportModeState_` | 物理状态内部可读，尚未封装传感器流 | IMU 轴向、四元数顺序、重力定义、噪声、时间戳；关节映射；实机电量与故障检查 |
| 足端状态 | Sport 状态的足力、足位和足速字段 | 只有接触足名称集合 | 接触布尔量与力值不可混用；需要时计算/发布足力和足位 |
| RGB 图像（V2） | `VideoClient.GetImageSample()` | 只有一次性外部视角截图 | 机载相机、持续采样、内外参、图像时间与质量状态 |
| 对齐深度、相机标定（V2） | 此处核对的 VideoClient 不提供完整 RGB-D 契约 | 无 | V2评估D435i或相机与雷达关联并验证标定；V1不需要该接口，不能凭前向RGB假定已有深度 |
| 三维点云 | 官方 ROS 示例 `/utlidar/cloud` | 无传感器点云输出 | V1匹配自带雷达的视场、遮挡、量程、扫描时间、坐标与噪声；核验点级时间和驱动，不套用MID360参数 |
| 后向观测 | 取决于实际传感器覆盖 | 无 | 支撑倒退走廊检查；覆盖不足时禁止自动退出 |
| 避障服务 | `ObstaclesAvoidClient.SwitchSet/Get`、`Move`、`UseRemoteCommandFromApi`、位置模式方法 | 无 | 如在实机使用须测坐标语义、权限、服务状态及制动效果；仿真仍需自己的障碍感知/规划 |
| 服务检查 | `RobotStateClient.ServiceList/ServiceSwitch` | 无 | 实机启动检查；不把服务开关作为任务状态机 |
| 补光/音量 | `VuiClient.SetBrightness/SetVolume` 等 | 无 | 弱光补光可选；仿真光照模型和检测效果另行验证 |

字段依据：[SportModeState IDL](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/idl/unitree_go/msg/dds_/_SportModeState_.py)、[LowState IDL](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/idl/unitree_go/msg/dds_/_LowState_.py)。图像依据：[VideoClient](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/go2/video/video_client.py)；激光依据：[官方 ROS 说明](https://github.com/unitreerobotics/unitree_ros2/blob/668d1ec5a05d1c38d3306bdca7d59f2ba3581a88/README.md)。

服务依据：[避障 Client](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/go2/obstacles_avoid/obstacles_avoid_client.py)、[RobotStateClient](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/go2/robot_state/robot_state_client.py)、[VuiClient](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/go2/vui/vui_client.py)。

## 5 应落实的接口清单

以下接口复用技术设计第10章，补充当前后端所缺的边界。名称是拟定契约；同进程初版可先以 Python 类型实现，再封装 ROS 2，不必先创建所有空包。

### 5.1 第一批：V1运动、自带雷达观测、质量与建图

| 接口 | 最小内容 | 当前状态 |
| --- | --- | --- |
| `get_capabilities()`，建议新增 | 支持的命令/传感器、速度限制、已验证地形工况、包络版本、控制器及协议版本；未验证能力显式标记 | 未实现 |
| `apply_motion(SafeMotionCommand)` | 三维速度、来源、command_id、epoch、sequence、发出时间及有效期；按来源有效期校验 | 只有本地 `move()` |
| `request_stop(reason)` / `MotionFeedback` | 停止原因、发送/接受是否已知、实际速度、运动状态、状态年龄和超时 | 只有 `stop()` 与瞬时速度 |
| `/sensors/imu`、关节状态、实机健康 | 带采样时间、坐标、单位、有效性和来源；IMU 100 Hz 为设计预算 | 未输出标准接口 |
| `/sensors/rgb/depth/camera_info`（V2，第一批不实现） | RGB-D 时间配对、内外参、深度单位、无效值及标定版本 | 未实现 |
| `/sensors/points`、后向覆盖状态 | 带时间的三维环境观测、覆盖范围、盲区及质量 | 未实现 |
| `/clock`、TF、`/localization/odom/status` | 仿真时间、map/odom/base_link/传感器转换、六自由度位姿及质量 | 只有仿真真值快照 |
| `ValidateConfiguration` / 健康检查 | 逐字段问题、依赖状态、数据年龄、能力和存储；失败不启动 | 部分低层检查 |

定位开发可先提供明确标注的 `ground_truth_debug` 数据源，便于调通导航；不得将其计作 SLAM 或实机定位验收。真值评测通道与自主传感器通道分开。

V1还需 `/mapping/map`、`/mapping/status`，输出map_id/revision、source、frame、有效性、地图文件与哈希；仅用传感器估计生成自主地图。不背图禁止先验地图、route_waypoints、中心线、终点坐标及真值位姿输入。

### 5.2 第二批：V1探索、规划、赛段和任务

| 接口 | 必需行为 | PRD |
| --- | --- | --- |
| `/terrain/grid`、局部三维占据 | 高程/坡度/粗糙度、未知/过期/禁行、更新时间与置信度 | FR03、04、06 |
| `check_passage()`，建议新增 | 输入当前姿态/三维包络及通道观测，输出可通行/阻塞/未知、净空与依据 | FR06 |
| 探索选择 → 导航子目标 | V1选择前沿或已观测未访问区域，按增益/代价/风险/重访评分；不输入隐藏终点 | FR15 |
| 全局规划 → `/navigation/path` | 起点、探索子目标、在线地图版本、路径、失败原因、超时；A* 为方案 | FR03、04、15 |
| 局部规划 → `/control/auto_intent` | 预测轨迹、速度候选、加速度及碰撞检查；无解输出停止意图 | FR03、04 |
| `NavigateSegment` action | 目标/赛段、进展、超时、取消及停止确认；不可达和退出结果 | FR03–06 |
| `ExecuteMission` action、`/mission/state` | 任务及赛段状态，启动/暂停/恢复/终止；结束结果及数据索引 | FR02、13 |
| `RequestControl` / `ResetSafetyLatch` | 安全 > 人工 > 自主；撤销旧控制权，故障锁存及人工复位 | FR07 |
| 保护 → `/control/safe_command` | 来源时效不被重复转发刷新；保护动作、限速及停止预算 | FR04、07、11 |

常规导航先固定 `vy=0`，按技术设计使用前向和偏航速度。侧移和倒退在传感器覆盖、运动及停止测试通过后开放。禁止把“参数允许负值”视为安全自动倒退已具备。

### 5.3 V1记录/控制台，V2追加探测

V1先实现任务、地图/轨迹、导航事件、增量补传、暂停接管和导出。下表的检测、目标定位、目标查询/复核及图像证据属于V2；不能等待这些功能才交付V1记录链。

| 接口 | 必需内容 | PRD |
| --- | --- | --- |
| `/perception/observations` | 类别、置信度、框、采集时间、证据、模型版本及质量 | FR08、11 |
| 目标关联/定位 | target_id、position_valid、map_revision、协方差、观测链与去重 | FR09 |
| `/events/live` + 事件存储 | event_id、task_id、event_seq、类型/等级/时间及载荷；落盘后通知 | FR07、10、12、13 |
| 任务/指令 HTTP API | 创建任务、提交操作、查询 PENDING/ACCEPTED/APPLIED/REJECTED/EXPIRED | FR02、07、13 |
| 目标查询/复核 API | `GET targets`、`PATCH review`；操作者、版本冲突与修改历史 | FR10 |
| 事件增量/导出 API | `events?after_seq=N`、导出任务、文件清单与哈希；支持异常中断 | FR10、13 |

具体路径采用技术设计 10.4 中的 `/api/v1/tasks`、`/commands/{id}`、`/targets/{id}/review`、`/tasks/{id}/exports` 和 `/api/v1/stream`。此处不另建一套重复业务协议。

## 6 若要求官方 SportClient 原样控制 MuJoCo

这是可选兼容适配工作；完成比赛并不要求先复刻全部原厂 SDK。建议上层依赖项目契约，仿真后端调用现有控制器，实体后端调用 SDK。

如果需要直接运行官方客户端，第一版仅实现：

1. 独立仿真运动服务进程，持续推进物理与策略；客户端不再调用 `step()`。RPC 回调入队，单一仿真线程修改 MuJoCo 数据。
2. 官方 `Request_/Response_` 类型、服务名 `sport`、版本探测；请求 `rt/api/sport/request`，响应 `rt/api/sport/response`。ROS 侧 `/api/sport/request` 是另一层名称表示，不混写为 SDK 原生主题。[官方频道命名](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/core/channel_name.py)
3. API 1008 映射速度、1003 映射停止；按实际实现考虑 1002。不支持的有应答 API 返回官方 `RPC_ERR_SERVER_API_NOT_IMPL=3203`；无应答请求不捏造响应，通过项目诊断暴露拒绝原因。[官方 RPC 服务端](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/rpc/server.py)
4. 发布最小可用运动遥测，明确哪些字段有效；标准 IDL 中没有项目所需完整有效性标志时，用配套诊断说明，不能将未知状态全部填零后宣称完整模拟。
5. 明确命令时效及隔离环境。SDK 标准速度载荷缺少项目的源时间/epoch/sequence，不能无损承载技术设计的全部 `MotionIntent` 契约；兼容桥应放在受控运动边界，项目内部继续执行控制权及有效期检查。
6. 仿真使用明确配置的独立 DDS 域/接口，和实机运行模式互斥；验证发现、进程退出、重启、时钟暂停及积压消息。
7. 用未经修改的官方客户端做互通验收，再声明支持这些 API；仅实现相同名称的 Python 方法不算协议兼容。

仿真运动服务需要至少支持实时运行模式，否则默认加速的无窗口物理循环会与真实墙钟客户端产生不一致的命令时效。

## 7 技术设计与当前实现需要对齐的事项

| 差异 | 影响及处理 |
| --- | --- |
| 技术设计 9.3/12.1 建议 200 ms 命令看门狗，当前配置为 300 ms 仿真时间 | 统一为经测试的显式配置；外部控制链还需单调时钟看门狗，不能只比较 `data.time` |
| 技术设计要求暂停/时钟回退撤销租约，当前没有任务租约 | 增加暂停、重启、异常锁存与恢复确认；不能在恢复后执行旧速度 |
| 当前异常为抛异常终止单次试验 | 对独立服务，需持续可观测的故障状态与已定义保护行为，不能把进程退出等同于已停稳 |
| `RobotState` 只有 yaw 与 upright_cos | 不足以覆盖六自由度 TF、RGB-D 投影、坡道包络与定位质量 |
| 当前 `close()` 请求零速度但不推进等待停稳 | 本地停止仿真与实机停止行为不同；不能直接复用于实机服务退出流程 |
| 当前任务函数把 `step()` 作为时钟推进方式 | 实机自行运行，应改为等待新状态/控制节拍；仅替换 `move()` 仍不能原样部署 |
| 技术设计 ROS 2 Jazzy，官方 ROS 说明主要列 Foxy/Humble，推荐 Humble | Jazzy 应视为待验证组合；检查 CycloneDDS、消息类型、QoS 和发现，不能因都使用 DDS 就认定兼容。[官方环境说明](https://github.com/unitreerobotics/unitree_ros2/blob/668d1ec5a05d1c38d3306bdca7d59f2ba3581a88/README.md) |
| 技术设计的旧参考场景/机器人描述未完全反映新的行走入口 | 行走现用作者机器人资源与组合场景，入口 `run_go2.sh`；`run_mujoco.sh/run_rescue.sh` 仍为站立演示，版本清单应分别记录 |
| 场景没有完整机载观测、动态障碍和目标 | V1补自带雷达等效流/IMU、未知布局及评估器；V2再补相机与目标，现有截图不等于传感器闭环 |

以上差异本轮仅记录，没有改动已有技术设计或运行参数。

## 9 已有证据与尚未满足的验收

本轮读取并核对既有 [基础报告](../../output/controller/validation.json) 和 [地形报告](../../output/controller/terrain-validation.json)，没有重新运行全部运动测试：

- 基础检查 13 项通过，包含前进、转向、停车、命令失效、复位历史及比赛起点坐标方向。
- 三项固定地形片段通过：作者首组 5 cm 台阶、比赛 12° 上坡片段、比赛第五组 4–12 cm 固定乱石。
- 这些是确定工况的单次冒烟检查。尚不满足 PRD 每赛段至少10次、全场10次至少8次成功、动态避障与感知统计等要求。
- 较陡 `cross_slope` 的 3 m 试验位置误差约 -9.6 cm，超过当前8 cm阈值；完整下坡、S 弯、死胡同、所有乱石与隧道均无全路线验收。
- 配置允许 `vy` 和负 `vx`，但现有报告未证明侧移、后退及相应制动能力。

官方平台接口、最终赛场规格、目标定义、允许先验地图与在线训练要求仍沿用 PRD 的待确认状态。上述未知项不会阻止先实现通用契约，但不能用当前开发场景假设替代官方验收配置。
