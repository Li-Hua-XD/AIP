# 不背图版导航方案：未知地图、未知终点

修订：v0.2　｜　2026-10-31　｜　优先实现　｜　需求依据：[PRD](./废墟智援_PRD_v0.1.md)

## 1 版本定位

导航模式为 `online_unknown`，功能首期为 V1。单台 Go2 EDU 16 GB / 100 TOPS 拓展坞版本，仅使用本体自带激光雷达、IMU及可用本体状态。V1 不使用 RealSense D435i、MID360，不依赖视觉或生命目标识别。V2 可在本导航版本上增加目标识别，并不要求先切换成背图版。

每次正式冷启动都没有赛道地图、预设路径或终点位置。机器人在任务中建立地图、估计位置、选择尚未探查的可达前沿并逐步探索；在探索中进入终点，由仿真评估器按位置验收。这里的“不背图”仍会建立和使用本次任务的在线地图。

## 2 自主输入与评估输入分离

| 数据 | 自主端 | 仿真/评估端 |
| --- | --- | --- |
| 本体包络、运控能力、传感器标定 | 允许 | 允许 |
| 起点坐标约定、许可边界、时间预算 | 允许；边界不能编码内部通道/路线 | 允许 |
| 雷达、IMU、状态及本次在线地图 | 允许 | 可记录 |
| 障碍真值、场景中心线、route_waypoints | 禁止 | 用于建世界和评测 |
| 终点位置、方向、距离、goal距离奖励 | 禁止 | 仅用于终点评估 |
| 真值位姿 | 正式验收禁止；调试需标ground_truth_debug | 用于误差、碰撞及到达判定 |
| 上次运行地图、失败分支或隐藏随机种子 | 冷启动禁止 | 可用于复现记录 |

仿真进程不可避免地加载完整 MJCF，但只向独立自主进程输出传感器和被允许的状态。自主进程不持有 `MjData`、世界几何查询接口或场景配置文件读取权限。命令只经过安全适配器进入仿真；渲染、射线和真值查询留在仿真端。

## 3 在线建图与定位

1. 核对自带雷达实际型号、扫描方式、点级/帧级时间、IMU来源、外参和遮挡；不能按 MID360 数据字段直接套用雷达惯性算法。
2. 首批静止观测建立起点局部地图，初始化六自由度里程计和质量状态。无需先扫描完整场地才允许运行。
3. 点云去自体与无效点，按传感器支持情况做运动补偿、降采样、配准和地面估计；未提供点时间时使用经过验证的近似或算法，明确运动速度限制和误差，不能伪造时间。
4. 维护连续 `odom` 与可校正 `map`，输出三维局部占据、2.5D地形和探索用二维栅格。坡道不压成纯二维定位；顶板和侧壁不误当作地面。
5. 地图显式区分自由、占据、未知和过期；每个单元保存质量/更新时间。局部占据按时间老化，永久几何与动态障碍分层。
6. 回环/全局校正后重投影前沿和分支记录，重新检查路径；大跳变暂停并复检。

现有官方或研究里程计算法须先通过实际雷达扫描格式、外参、时间和机载环境验证再冻结。V1 传感器仿真以射线采样生成三维点云为主，不用理想全景深度或额外传感器补足本体盲区。

## 4 无终点坐标的探索与规划

探索不是沿某个隐藏终点方向贪心前进。第一版采用可解释的前沿探索：

- 从在线栅格提取“已知自由区域与未知区域交界”，聚类并过滤面积过小、过期或不可达前沿。
- 在前沿的已知自由侧生成观察位姿，校验站立空间、净空、可达路径及停止距离；不把未知格中心直接作为可行落脚点。
- 使用 `score = w_gain*gain - w_path*path_cost - w_risk*risk - w_repeat*repeat_cost` 排序。各项归一化并固定权重，信息增益只由当前地图与传感器模型估算，不能查询隐藏几何或终点距离。
- 在已知可通行区域上用A*到观察位姿，局部速度采样器持续检查三维扫掠和地形能力。未知边界随新观测推进；无可行速度输出停止。
- 持续保存返回轨迹、前沿状态和失败原因。局部被挡先观察/等待，再重规划或换前沿；同一失败分支限制重试，观测变化才解禁。
- 另建机体访问掩码，记录实际走过的可通行区域。雷达看见不等于机器人到过：当没有有效前沿或发现大块已观测未访问区域时，从其已知自由空间生成访问子目标，继续搜索隐藏终点。采样间距按统一最小验收区域尺度预先冻结，不能由终点真值反向布点。
- 用子目标超时、无进展时间、总任务时限和探索距离预算防止循环。预算在测试前冻结，不因未到终点无限延长。

状态可使用 `INITIALIZING → EXPLORING → NAVIGATING_FRONTIER → OBSERVING` 循环，异常转 `REPLANNING/RETREATING/PAUSED`。前沿与已知未访问区域均无有效候选时输出 `NO_FRONTIER`（无探索/访问候选），耗尽预算输出 `EXPLORATION_TIMEOUT`。地图已观测区域无前沿不等于已到终点，也不意味着机体已遍历可达空间；优先按访问掩码继续选择子目标。

## 5 仿真终点验收与实机边界

用户确认：现实场景的终点验收尚不确定，仿真直接根据位置验收。

评估器独立保存终点区域与 MuJoCo 真值坐标系。任务开始前冻结参考点（例如机身中心的地面投影）、区域内判定、边界容差、速度阈值、停稳保持时长和超时。只在真值参考点进入终点区域时向监督器发出终止事件、请求停止；连续保持在区域内并停稳后计完成。若滑出、碰撞、倾倒或超时，记失败/未完成，不能只取曾经擦边进入的单帧。

自主规划器不获得终点坐标、距离或真值位姿。终止事件只结束本轮，不作为前沿打分或在线调参反馈；评估器失效时停止并记评估失败。报告明确此能力是“未知终点探索 + 外部位置验收”，不能表述为机器人通过雷达识别出了终点语义。

实机配置为 `real_finish_policy=pending`。可以完成建图、定位、前沿探索、分段通行与故障测试；完整起终点实机验收在官方/现场规则确定后补齐。若最终由操作员/裁判确认完成，接口单独记录外部完成来源；若需自动识别终点，再定义可观测特征和所需传感器，不擅自加入视觉或几何标志。

## 6 配置与交付示意

以下为待实现契约，不是当前可运行配置：

```yaml
feature_stage: V1
navigation_mode: online_unknown
prior_map: null
route_waypoints: null
goal_pose: null
sensors:
  navigation: [builtin_lidar, builtin_imu, robot_state]
  realsense_d435i_enabled: false
  mid360_enabled: false
perception:
  life_detection_enabled: false
mission:
  finish_policy: external_sim_position_judge
  real_finish_policy: pending
  exploration_budget_profile: null # 正式试验前必须冻结
```

终点区域和真值变换只存在于评估端配置，不放进这份自主配置。部署到实机探索试验时不允许使用仿真完成策略，也不生成假完成状态。

验收采用 PRD 的 T01–08、T11–17、T19，重点验证冷启动与真值隔离、地图/定位精度、未知布局及未知终点探索、已观测未访问区域搜索、无候选/超时处置和地图导出。成功率按不背图单独报告，保留未到达、走错分支、漂移和超时样本。实机终点规则未冻结时只发布分项结果。
