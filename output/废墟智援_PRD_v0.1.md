# 废墟智援四足机器人搜救系统产品需求文档

版本：v0.1　｜　日期：2026年10月28日　｜　状态：需求评审稿

本文面向参赛团队的产品、算法、仿真、机器人控制和测试成员，用于明确首版产品范围、开发顺序与验收依据。首版目标是在指定废墟场景中完成“自主通行、目标探测定位、信息回传、结果复核”的任务闭环，形成可重复演示、可追溯验证的参赛系统。

## 1 产品定位与需求依据

### 1.1 背景与产品目标

废墟搜救存在视线受阻、地形复杂、通道受限与环境危险等问题。产品以四足机器人为移动载体，协助操作员探查模拟废墟、发现疑似生命目标并记录其位置。操作员通过控制台观察任务、复核发现、接管机器人，测试人员利用同一套日志验证系统表现。

首版围绕三个可交付目标展开：完成分赛段自主通行及全场联调；形成疑似目标发现到人工复核的信息链；生成能够支撑研制报告、演示视频与答辩的数据和证据。项目成果定位为竞赛原型，实际灾害救援部署需要另行验证。

### 1.2 依据和标注规则

唯一赛事依据为用户提供的六页《第二届北京市大学生“人工智能+”创新大赛赛题规则》“废墟智援”赛题。下文以“官方要求”“产品方案”“建议指标”“待确认”区分信息性质。建议指标是团队内部验收目标，不代表赛事评分线，也不是已经取得的测试结果。

| 类别 | 已知事实及约束 | 来源页码 |
| --- | --- | --- |
| 核心任务 | 运动控制与路径规划；生命目标探测、定位、识别及信息回传 | 第3页 |
| 核心能力 | 地形自适应行走、弱光识别、动态避障、狭小空间通行、多传感器抗干扰 | 第2页 |
| 载体与平台 | 四足机器人；允许商用本体或仿真虚拟机器人；本体品牌和仿真平台不限 | 第4页 |
| 场地 | 12×10米；坡道、S弯、死胡同分岔、五处乱石、三类隧道 | 第6页 |
| 赛制 | 校内预选采用指定线上平台；企业选拔以线下为主，部分线上仿真 | 第3页 |
| 评分 | 实操与答辩加权，具体权重和量化评分阈值未给出 | 第3页 |

### 1.3 首版边界与前提

产品方案：本地仿真平台采用 MuJoCo，优先完成仿真系统闭环，控制接口保留实机适配能力。是否购买或接入实体机器人，由设备条件及参赛阶段要求决定；仿真通过不等于已经满足线下实机要求。暂按机器人已有可调用的基础步态控制能力规划，若本体不具备该能力，需要增加底层运动控制开发周期。

首版不包含搬运伤员、机械臂清障、医疗诊断、多机器人协同与实际灾害现场部署。视觉发现统一称“疑似生命目标”，不得仅凭图像识别推断存活状态。官方背景提及模型在线训练，其强制性和验收方式待答疑确认；首版先支持数据记录、版本管理和受控的仿真适应验证，现场自动更新运动策略须另行评审。

## 2 用户场景与版本范围

### 2.1 用户及核心需求

| 用户 | 使用场景 | 必须获得的结果 |
| --- | --- | --- |
| 任务操作员 | 配置任务、观察运行、处理告警 | 知道机器人位置、当前动作、异常原因，并能暂停或接管 |
| 目标复核员 | 查看疑似目标及证据 | 确认目标类别、位置、置信度和图像，标记复核结果 |
| 算法与控制成员 | 对比算法或参数版本 | 复现实验条件，定位通行失败、漏检与误报原因 |
| 测试与演示成员 | 执行验收、答辩展示 | 一键导出任务摘要和原始记录，关联演示证据 |

### 2.2 典型任务场景

场景A：机器人从起点出发，上下坡并通过S弯，遇到死胡同时识别道路不连通，受控退出并重新规划。通过五处乱石区时，根据可通行性调整速度与步态请求；无法安全继续时暂停并说明原因。

场景B：机器人接近隧道前估算有效宽高，结合机器人外形包络及安全余量判断是否可通行。对官方描述中应放弃的隧道1做出拒绝进入的决策；隧道2圆管和隧道3方涵按实际配置验证，不能仅凭编号假定可通行。

场景C：行进中发现疑似目标，记录证据、时间和场景坐标，回传控制台并请求人工复核。在弱光或遮挡下无法可靠识别时显示“待复核”；定位不可用时保留发现记录并标记“位置无效”，不得输出看似精确的坐标。

### 2.3 优先级与发布范围

P0表示首版交付门槛，P1表示增强验证项，P2表示后续探索项。优先级是团队开发顺序，官方提出的能力均需保留对应验证计划，不能因标为P1而视为已获豁免。

| 优先级 | 交付内容 | 发布要求 |
| --- | --- | --- |
| P0 | 场景配置、初始化、自主通行、动态避障、受限通道判断 | 有分段记录及全场运行证据 |
| P0 | 疑似目标识别、定位、去重、回传、人工复核 | 有正负样本与定位真值对比 |
| P0 | 控制台、暂停接管、安全停止、日志与结果导出 | 有异常注入及恢复记录 |
| P1 | 弱光优化、多传感器抗干扰、风险区域预警 | 有能力边界与失败样本，参赛前完成专项验证 |
| P1 | 实机适配及仿真与实机差异验证 | 若采用实机，进入现场前完成 |
| P2 | 多机器人协同、拓展作业与在线策略更新 | 独立需求评审，不阻塞首版 |

### 2.4 任务主流程

加载场景与机器人配置 → 检查传感器和定位 → 选择任务并启动 → 感知与规划 → 安全校验后执行运动 → 同步探测与回传 → 处理异常或人工接管 → 到达终点或人工终止 → 导出任务报告。

通行与探测并行执行；是否在发现目标后停靠由任务配置决定。比赛流程如另有规定，应由配置覆盖并保留版本记录。

## 3 通行与运动功能需求

### FR01 场景与机器人配置 P0

系统须加载同一份场景配置，包含场地边界、赛段、障碍物、通道参数、目标布置版本及坐标系。目标真值仅供测试端使用，不能作为自主识别模块的输入。机器人配置包含外形包络、可调高度范围、速度限制、传感器外参和控制接口版本。

验收：配置缺项或单位不一致时阻止启动并给出字段名；每次任务导出配置快照。场地参考图中的细小标注不直接作为尺寸依据，宽度、高度、坡度及乱石尺寸使用赛题组后续配置表。

### FR02 初始化与任务启动 P0

系统须检查传感器数据新鲜度、定位状态、控制通道和日志存储；实机增加电量及安全停止通道检查。操作员设置任务名称、起终点和运行模式后启动。关键检查不通过时保持待命，展示原因与修复提示。

验收：模拟传感器未连接、定位失效或控制通道不可用，均不得进入自主运动状态；检查结果写入任务日志。

### FR03 自主规划与地形通行 P0

机器人须根据当前位姿、环境观测及通行约束生成可执行路径，并向底层控制器输出限幅后的运动请求。上坡、下坡、S弯和乱石区使用相应的速度、姿态或步态配置；超过已验证能力边界时停下并报告，禁止盲目提高速度或冲撞障碍。

验收：各赛段有独立测试记录，包含完成状态、耗时、接管次数、碰撞和倾倒事件；进入未知地形前能够降速或停止。

### FR04 动态避障与重新规划 P0

机器人须持续监测路径占用变化；障碍进入安全距离时先减速或安全停止，再尝试重新规划。规划超时、路径不可达或连续失败时转为等待人工处理。安全距离和规划超时是配置参数，应根据机器人制动能力及实测时延确定。

验收：横穿、静止封路和突发靠近三类障碍均触发对应处理；记录感知时间、决策时间、控制生效时间和最小间距。

### FR05 死胡同退出 P0

系统须结合地图连通性和近期进展判断死胡同，标记不可达分支。退出前检查后方空间；具备后方感知且空间允许时受控倒退，否则请求人工接管。不得在狭窄区域强行原地转向。

验收：退出后规划不立即重复进入同一无效分支；后方信息不足时停止并说明原因。

### FR06 隧道宽高判断 P0

系统须比较通道有效截面与机器人包络，纳入姿态误差、定位误差和安全余量。具备且已验证调姿能力时允许调整姿态；不满足条件或测量置信度不足时拒绝进入。

验收：隧道1被识别为应放弃通道并记录理由；圆管、方涵分别测试通过与受限情况；拒绝后能够重新规划或结束该分支。

### FR07 运动状态与保护 P0

系统须监测倾角、运动进展及控制异常，识别失稳风险、长时间无进展等事件。保护动作采用机器人平台支持并验证的安全停止方式，保留姿态支撑；实机需要独立、可触达的停止手段。

验收：保护动作具有最高控制优先级，异常解除后仍须由操作员确认恢复，不能自行继续运动。

## 4 目标探测与信息回传需求

### FR08 疑似生命目标识别 P0

系统须对官方允许的目标类别进行检测，输出类别、置信度、观测时间与证据图像。目标类别、大小、遮挡形式及是否采用假人等对象均待官方说明；不预先把某种对象视为官方唯一目标。

检测阈值、连续观测确认条件及去重阈值须可配置并记录版本。单帧低置信度结果可进入候选队列，达到确认条件后才形成告警。验收覆盖正常光照、弱光、局部遮挡以及相似非目标干扰物。

### FR09 目标定位与去重 P0

系统须将目标观测转换到任务场景坐标，保存坐标系标识、位置有效性及误差或不确定度信息。相邻帧、重复巡查发现的同一目标合并为统一编号，保留历次证据；同一区域多个不同目标不得简单合并。

验收：通过有真值的测试场景计算定位误差，验证多次观测去重和相邻目标分离；缺少有效深度或定位时明确标记位置无效。

### FR10 回传与人工复核 P0

控制台须显示目标编号、类别、位置状态、置信度、时间、证据与复核状态。复核员可标记“确认目标”“误报”“待复核”，补充备注；系统保留修改人、修改时间和变更前状态。

通信中断时机器人本地缓存目标与事件，恢复后按事件编号补传并去重。目标复核结果可回流为后续标注数据，不在运行中自动改变已发布模型。

### FR11 弱光与多传感器异常处理 P1

系统须记录光照测试条件及传感器可用状态。弱光下可使用允许的补光、图像处理或附加传感器方案，但具体硬件选型与采购不在本稿中锁定。单路传感器丢帧、延迟或失效时，系统须显式标记降级；关键感知不足则停止自主运动。

验收：以同一组目标分别测试正常光照与弱光，报告指标差异；逐项注入传感器故障，验证不会继续依赖过期观测。

### FR12 风险识别预警 P1

首版风险类别限定为能由现有传感器观测并验证的阻塞、限宽限高和失稳风险。风险事件须包含类型、区域或位置、触发依据、严重等级与建议动作。气体、温度、结构坍塌等能力只有在配备对应传感器并通过测试后才可纳入宣传及验收。

### FR13 任务记录与导出 P0

系统须记录任务状态、轨迹、目标、告警、控制权变化、人工接管、模型和配置版本。支持导出任务摘要、结构化明细和证据索引；发生中断时仍可导出已保存记录。

验收：导出的目标数、事件数与控制台一致；可通过任务编号找回相应日志和图片。复盘模式显示“历史回放”，不得与实时任务混淆。

## 5 控制台交互与系统接口

### 5.1 页面与主要操作

| 页面 | 核心内容 | 主要操作及反馈 |
| --- | --- | --- |
| 任务配置 | 场景、机器人、模型、任务配置版本 | 校验、启动；失败显示具体检查项 |
| 运行监控 | 地图、路径、位姿、视频、状态、控制权 | 暂停、接管、停止；显示执行确认与失败原因 |
| 目标与告警 | 发现列表、证据、位置有效性、风险 | 查看、复核、备注；保留变更历史 |
| 任务复盘 | 轨迹、时间线、统计及版本 | 筛选、回放、导出；明确标记历史数据 |

地图与视频必须展示数据时间或延迟状态。失联后保留最后位置，但同时显示数据已过期。关键按钮不能只改变界面文字，必须等待机器人执行反馈或明确显示“指令未确认”。

### 5.2 任务状态与控制权

任务状态：待命 → 自检 → 就绪 → 运行 → 完成；运行可转为暂停、故障或终止。暂停后需重新满足检查条件并人工确认才可恢复。完成及终止任务不可直接续跑，应创建新任务；故障记录必须保留。

控制模式独立于任务状态，分为自主与人工。接管时先撤销自主控制权限，机器人确认后接受人工指令；恢复自主前重新验证定位、感知与路径。优先级为安全保护高于人工控制，人工控制高于自主控制。

### 5.3 关键数据字段

| 数据对象 | 最小字段集合 | 约束 |
| --- | --- | --- |
| 任务 | task_id、场景版本、模型版本、起止时间、状态、结束原因 | 编号唯一；时间统一基准 |
| 位姿 | 时间戳、frame_id、x/y/z、姿态、定位状态 | 坐标单位米；姿态单位明确 |
| 目标 | target_id、类别、置信度、坐标、位置有效性、证据、复核状态 | 无效位置存空值；不可用零代替 |
| 事件 | event_id、task_id、时间、类型、严重等级、处理状态 | 支持断线补传去重 |
| 控制指令 | command_id、发出时间、有效期、模式、参数、确认状态 | 过期拒绝；同一指令幂等处理 |

### 5.4 接口行为要求

MuJoCo 本地仿真适配层或本体适配层负责传感器输入、运动指令及执行反馈，向上提供统一的逻辑接口；定位与感知模块输出有时间戳的数据；规划模块输出路径和失败原因；记录模块关联任务编号保存数据。具体协议、消息频率与软件框架在技术设计中确定。

通信须具有心跳、超时、重试和执行确认机制。控制台心跳连续丢失的建议初值为1秒，但必须按链路实测调整。超时后机器人进入已验证的安全停止状态；重连后先同步状态，再由人工确认恢复，禁止补发过期运动指令。

## 6 质量要求与建议验收指标

以下全部量化阈值均为内部建议，赛事文件未公布这些数值。指标在机器人、场景、目标与光照条件冻结后评审；若调整，必须记录理由和版本。当前没有实测结果。

| 指标编号 | 项目 | 建议目标与统计口径 |
| --- | --- | --- |
| Q01 | 分赛段通行成功率 | 每个赛段至少10次，成功率≥90%；成功须无碰撞、倾倒及人工接管 |
| Q02 | 全场自主任务成功率 | 固定配置10次，至少8次到达终点并保存结果；规定必须处理的任务全部执行 |
| Q03 | 动态避障 | 三类障碍各10次；测试中零碰撞；停止或改道符合预期，不把停滞计为通行成功 |
| Q04 | 受限通道拒绝 | 不可通行条件至少10次，全部在进入前拒绝；另设可通行样本防止一律拒绝 |
| Q05 | 目标召回率 | 正常光照≥90%，约定弱光条件≥80%；按独立目标实例匹配统计 |
| Q06 | 目标识别精确率 | 正常光照≥90%，约定弱光条件≥85%；重复告警不重复算真阳性 |
| Q07 | 目标位置误差 | 有效定位目标的平面误差中位数≤0.30米，P95≤0.50米；同时报告定位有效率 |
| Q08 | 信息回传时延 | 正常链路下告警生成到控制台展示P95≤1秒，统计不少于100条 |
| Q09 | 暂停指令响应 | 正常链路下指令发出到平台接受停止请求P95≤300毫秒；另测停止距离 |
| Q10 | 断线与恢复 | 10次断线注入均触发安全行为；重连不自动运动，已缓存事件不丢不重 |
| Q11 | 稳定性 | 连续30分钟受监护运行，无进程崩溃、失控或关键日志缺失 |
| Q12 | 数据完整性 | 完成及异常终止任务均能导出；任务、事件与证据关联完整率100% |

### 6.1 评价口径

通行成功率＝符合成功条件的运行次数÷有效测试次数。全场每次测试须记录超时与失败原因；在测试前冻结完成时限，不以无限等待获得成功。设备故障导致的无效测试单独列明，不得静默删除失败结果。

召回率＝正确检出的目标数÷真实目标数；精确率＝正确检出数÷全部检出数。位置误差须在统一场景坐标系下与真值比较。重复发现同一目标先按预先约定的匹配规则去重，再统计；同时报告误报数、漏检数与每次任务误报告警数。

目标评测至少包含50个独立布置实例及20段无目标负样本序列，按光照分别统计。训练与测试按场景或采集序列分开，不能将相邻视频帧随机拆开后声称泛化通过。识别匹配阈值、弱光照度与定位有效率目标均在测试前冻结。

### 6.2 指标适用边界

控制响应时延不等于机器人完全停止时间。实机须另测不同速度和地形下的停止时间与距离，并据此配置安全距离。零碰撞是本批测试通过条件，不代表对所有实际环境的安全保证。

### 7.2 测试记录要求

每条记录包含用例编号、执行人、时间、场景版本、随机种子、机器人参数、模型版本、运行环境、输入条件、结果、日志路径与失败原因。光照记录测量值或可复现的仿真配置；网络测试记录时延、丢包及断线持续时间。仿真与实机结果分别报告。

测试过程中使用目标真值计算指标，但系统自主运行部分不得读取测试目标答案。模型选择、阈值调整与最终测试应分开记录，避免在验收样本上反复调参后直接宣称通过。

### 7.3 首版发布门槛

评审材料应同时呈现成功案例、失败案例及适用边界。竞赛提交前另做一次规则符合性核查，确认是否需要实机、指定线上平台兼容性及最新官方要求。

## 8 开发计划与实施约束

### 8.1 六周参考计划

以下为项目启动后的相对安排，并非官方赛程。团队获取平台和设备后重新估算；本体控制、传感器集成或线上平台接口差异可能增加周期。

| 第2周 | 初始化、定位、基本控制、L1测试 | 直行及上下坡闭环，暂停和停止可用 |
| 第3周 | S弯、死胡同、乱石、隧道判断及避障 | L2与L3通行用例可执行，失败可记录 |

### 8.2 角色分工与资源

按3至5人团队安排工作包：产品与集成负责需求、控制台和进度；规划与控制负责通行、避障和保护；感知负责目标、定位与弱光；仿真与测试负责场景、真值和回归；材料负责人负责报告、视频与答辩。人数不足时合并岗位，但关键验收由非直接实现者复核。

资源清单至少包含开发电脑、MuJoCo 本地仿真平台与参考模型、机器人模型或本体、传感器、测试存储和演示投屏设备。实机团队补充安全隔离与防护物品。采购前核对已有设备、接口、预算及到货时间，本稿不虚设价格或锁定品牌。

### 8.3 主要风险与应对

| 风险 | 对产品的影响 | 应对措施 |
| --- | --- | --- |
| 官方尺寸、目标定义或平台接口未明确 | 场景和指标返工 | 参数化配置，第1周建立答疑清单 |
| 底层控制能力不足 | 高层路径可行但机器人无法执行 | 先验证L1和停止动作，必要时调整本体或范围 |
| 仿真与实机存在差异 | 现场通行或定位失败 | 分阶段验证摩擦、传感器噪声和控制时延 |
| 弱光或遮挡导致漏检 | 目标发现不完整 | 保留证据，专项评测，允许人工复核 |
| 网络或计算资源不足 | 告警滞后、控制异常 | 本地运行核心链路，限流缓存并测试断线 |
| 训练数据与测试数据混用 | 指标失真 | 按场景拆分、记录来源、冻结验收集 |

### 8.4 安全与数据约束

官方要求：不得使用涉密、敏感灾害现场影像；实机演示设置安全隔离并佩戴防护用品；禁止无人监护长时间运行；不得改造机器人高压、动力部件。数据集需登记来源、许可和用途。禁止接入企业内网；如需外网API，按规则赛前报备及联调。

产品方案：核心控制、识别与记录优先在本地完成，外网不可用时仍可安全结束任务。在线训练仅在受控流程中验证，保留基线模型、训练记录与回退版本。
